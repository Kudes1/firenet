# firenet

firenet — веб-приложение для управления распределённым firewall на базе
`iptables` и `ipset`. В интерфейсе можно вести топологию сети, подсети,
сети и правила фильтрации, проверять их и компилировать правила для
устройств. Ядро рассчитывает размещение правил на всех транзитных
маршрутизаторах с учётом резервных маршрутов.

Данные приложения хранятся в PostgreSQL. Все пользовательские сценарии
работы выполняются через веб-интерфейс; Docker Compose — основной способ
запуска.

## Быстрый запуск

Требуются Docker Engine и Docker Compose v2.

```sh
cp .env.example .env
# задайте надёжные значения POSTGRES_PASSWORD и FIRENET_ADMIN_PASSWORD
docker compose up -d --build
```

После запуска откройте [http://localhost:8787](http://localhost:8787) и
войдите с логином и паролем из `FIRENET_ADMIN_USER` и
`FIRENET_ADMIN_PASSWORD` в `.env`. Этот пользователь создаётся как
администратор только при первом запуске с пустой базой данных.

При первом запуске приложение применяет миграции и импортирует начальную
версию данных из `topology.yaml`, `subnets.yaml` и `rules.yaml`, если они
находятся в корне проекта. Дальше изменения вносятся и сохраняются через
веб-интерфейс.

## Работа с приложением

Интерфейс позволяет:

- редактировать топологию, подсети, сети, наборы и объединения;
- создавать связи между устройствами и правила фильтрации;
- проверять конфигурацию, диагностировать связность и компилировать
  правила;
- работать с личными черновиками, историей версий и пользователями.

Подтверждать черновики, восстанавливать версии и управлять пользователями
могут только администраторы.

## Обслуживание

```sh
docker compose ps              # состояние сервисов
docker compose logs -f app     # логи приложения
docker compose up -d --build   # пересобрать и применить обновление
docker compose down            # остановить и удалить контейнеры
```

Команда `docker compose down` не удаляет именованный том `firenet-db`,
поэтому данные PostgreSQL сохраняются. Чтобы удалить приложение вместе с
данными, выполните `docker compose down --volumes`.

## Конфигурация

Docker Compose считывает следующие значения из `.env`:

| Переменная | Описание |
|---|---|
| `POSTGRES_PASSWORD` | пароль пользователя PostgreSQL `firenet` |
| `FIRENET_ADMIN_USER` | логин первого администратора |
| `FIRENET_ADMIN_PASSWORD` | пароль первого администратора |

Порт интерфейса на хосте — `8787`. При необходимости изменить его поменяйте
публикацию порта в `docker-compose.yml`.

## Разработка

Для проверки изменений исходного кода:

```sh
go build ./...
go vet ./...
gofmt -l .
go test ./...
node --test 'internal/httpapi/web/*.test.js'
```

После изменения файлов из `internal/httpapi/web/` пересоберите образ:

```sh
docker compose up -d --build
```

## Структура проекта

```
cmd/firenet/       точка входа приложения
internal/app/      ядро бизнес-логики
internal/httpapi/  HTTP API и встроенный веб-интерфейс
internal/pgstore/  хранение проектов и версий в PostgreSQL
internal/auth/     аутентификация и пользователи
internal/topology/ модель сети: устройства, связи, подсети и зоны
internal/rules/    модель правил фильтрации
internal/graph/    построение графа маршрутизации и поиск путей
internal/compiler/ размещение правил по устройствам
internal/render/   рендер iptables/ipset-скриптов
```
