# Дизайн: UI черновиков и версий

Дата: 2026-08-26
Статус: утверждён к планированию

## Цель

Сделать веб-интерфейс совместимым с реализованным API версий и черновиков:
подтверждённая версия открывается только для чтения, а любые изменения
выполняются в черновике, выбранном в текущей вкладке браузера.

## Контекст черновика

`internal/httpapi/web/common.js` хранит идентификатор активного черновика в
`sessionStorage` по ключу `firenet-draft-id`. Поэтому разные вкладки могут
работать с разными черновиками одного пользователя. При отсутствии
идентификатора вкладка находится в read-only режиме и читает текущую
подтверждённую версию.

`apiPath(suffix)` возвращает один из путей:

- `/api/drafts/{id}/{suffix}` при выбранном черновике;
- `/api/versions/current/{suffix}` в read-only режиме.

`assertEditable()` запрещает сохранение вне черновика до выполнения HTTP
запроса. `Api` запоминает `X-Draft-Revision` из ответов черновика и передаёт
его при следующем `PUT`, сохраняя CAS-защиту API.

## Общий интерфейс

На всех рабочих страницах показывается постоянный баннер:

- без черновика — номер текущей версии, признак «только чтение» и действие
  «Открыть черновик»;
- с черновиком — имя, статус и действие возврата к текущей версии.

В sidebar добавляются страницы «Черновики» и «История». Страницы управления
черновиками, историей и пользователями не показывают общий баннер, поскольку
дают собственный контекст действий.

## Рабочие страницы

Страницы topology, subnets, networks, sets, unions, links, rules и diagnose
все чтения и операции используют `apiPath`. Сохранение на страницах с
редактированием возможно только с активным черновиком. Операции compile,
validate, lint, link-exports и diagnose читают выбранный черновик либо
подтверждённую версию, не создавая изменений.

## Страница черновиков

`/ui/drafts` позволяет создать, выбрать и удалить собственный черновик.
Admin может переключиться на просмотр всех черновиков, увидеть автора и
подтвердить чужой или свой черновик. Для выбранного черновика отображается
diff с базовой версией и конфликтующие сущности. Ответ `409` подтверждения
оставляет черновик выбранным и показывает конфликтные значения, чтобы автор
исправил их в редакторах.

## Страница истории

`/ui/history` выводит историю версий, diff выбранной пары версий и позволяет
admin создать новую версию восстановлением выбранной. После успешного
восстановления интерфейс обновляет историю и возвращается к read-only
текущей версии.

## Ошибки и тестирование

Все HTTP-ошибки отображаются существующим `showBanner`; `401` перенаправляет
на страницу логина. Проверки выполняются без браузера: через `node --test`
с DOM-стабами. После изменений запускаются также `go build ./...`,
`go vet ./...`, `gofmt -l .` и `go test ./...` в worktree.
