# Дизайн: симуляция трафика между двумя IP

Дата: 2026-08-23
Статус: согласован с пользователем (подход A, вариант карты A1)

## Цель

Дать возможность увидеть, как пойдёт трафик от одного IP до другого IP:
все возможные пути — ровно те, которые находит ядро при компиляции правил, —
плюс вердикт и объяснение по каждому транзитному роутеру.

## Принятые решения (из брейншторма)

- Результат: пути + вердикт + объяснение «почему».
- Конечные точки: только IP из объявленных подсетей; IP вне всех подсетей — ошибка.
- Прото/порты: опциональны; без них — матч всех правил между подсетями src→dst.
- Точка входа: веб-UI + ядро в `internal/app` (CLI не трогаем, YAGNI).
- Визуализация: отдельная страница + подсветка путей на карте топологии
  (выделение общего рендера `netmap.js` из `topology.js`).

## Подход

Симуляция поверх **скомпилированных** правил (`compiler.Compile`): вердикт
гарантированно совпадает с тем, что реально попадёт в iptables. Логика
placement не дублируется.

## Секция 1. Ядро

### Новый пакет `internal/simulate`

Модель и чистая логика симуляции; не знает про HTTP/файлы.

```go
type Flow struct {                       // какой трафик симулируем
    Src, Dst netip.Addr
    Proto   rules.Proto                   // "" = любой
    SrcPorts, DstPorts []string           // пусто = любые
}

type Report struct {
    SrcSubnet, DstSubnet string           // имена подсетей, куда резолвнулись IP
    Paths []PathResult
}

type PathResult struct {
    Nodes    []graph.Node                 // весь путь: подсеть → роутеры/L2 → подсеть
    Routers  []RouterVerdict              // по каждому транзитному роутеру
    Verdict  rules.Action                 // первый DROP обрывает путь; иначе итог
}

type RouterVerdict struct {
    Router      string
    Action      rules.Action               // действие сработавшего правила или DefaultAction
    MatchedRule string                     // имя policy-правила (Comment), "" если дефолт
    Reason      string                     // человекочитаемое объяснение
}
```

### Хелпер матча в `internal/compiler`

`MatchFlow(rs DeviceRuleset, src, dst netip.Addr, proto rules.Proto,
srcPorts, dstPorts []string) *CompiledRule` — параметры развёрнуты явно, чтобы
не создавать зависимость `compiler → simulate` (`simulate` и так импортирует
модель компилятора). Семантика ровно как у
рендера:

- пустой `SrcSet`/`DstSet` = безусловный матч по этой стороне;
- ipset-матч = принадлежность адреса трафика CIDR'ам соответствующего
  `IPSet.CIDRs` из `rs.IPSets`;
- прото: any-правило матчит любой прото;
- порты: пустой список портов правила = любой порт; иначе пересечение непустое;
- first-match по порядку `rs.Rules`; промах → `nil`, вердикт `DefaultAction`.

### Оркестрация `app.Simulate`

Зеркало `app.Compile`: те же опции загрузки (topology/subnets/rules YAML,
`MaxHops`, `MaxPaths`) плюс `Flow`.

1. Загрузить topo/subnets/rules, провалидировать.
2. Резолв `Src`/`Dst` → подсеть через `netip.Prefix.Contains` (включая адреса
   сетов). Не нашли — ошибка.
3. `compiler.Compile` — один раз, как для реальной генерации.
4. `g.AllSimplePaths(subnetNode(src), subnetNode(dst), limits)` — тот же поиск
   путей, что у компилятора (filtered-links, `ErrTooManyPaths` наследуются).
5. Для каждого пути — вердикты роутеров через `MatchFlow` над их `DeviceRuleset`.

Слои остаются чистыми: `simulate`/`compiler` не знают про app/HTTP, `app`
только оркестрирует.

## Секция 2. HTTP API (`internal/httpapi`)

- `POST /api/simulate` — тело
  `{"src":"10.0.1.5","dst":"10.0.2.7","proto":"tcp","srcPorts":[],"dstPorts":["443"]}`
  (proto/порты опциональны).
- Хендлер читает topology/subnets/rules из `ProjectStore` (как `compile`),
  вызывает `app.Simulate`, возвращает JSON `simulate.Report`.
- Ошибки: невалидные данные / IP мимо подсетей / `ErrTooManyPaths` → `422`
  с текстом; проблемы хранилища → `5xx`.
- Отдельный DTO-слой не нужен — модель уже JSON-дружелюбная.
- Регистрация: `mux.HandleFunc("POST /api/simulate", h.simulate)` в `NewServer`.

## Секция 3. Веб-UI (`internal/httpapi/web/`)

Новая страница `/ui/simulate` (`simulate.html` + `simulate.js`), ссылка в
сайдбаре, стиль существующих htmx+alpine страниц.

- Форма: src IP, dst IP, протокол (any/tcp/udp/icmp), порты → `POST /api/simulate`.
- Результат:
  - сводка: резолвнутые подсети src/dst, число путей;
  - карточка на каждый путь: цепочка узлов (подсеть → роутеры/L2 → подсеть)
    с бейджами вердикта (accept — зелёный, drop — красный, дефолт — серый)
    и итоговым вердиктом пути;
  - раскрытие роутера — `Reason` + имя сработавшего правила;
  - «путей нет» → явное «недостижимо».
- Карта топологии (вариант A1): из `topology.js` выделяется общий модуль
  `netmap.js` с чистыми функциями отрисовки (узлы/рёбра/camera); страницы
  топологии и симуляции используют его. На странице симуляции карта read-only:
  форма слева, карта справа, найденные пути подсвечены цветом по номеру пути,
  остальные рёбра приглушены. Существующие `topology_render.test.js` /
  `camera.test.js` проходят без правок ассертов — это регресс-проверка
  рефакторинга.

## Секция 4. Ошибки и краевые случаи

- IP вне всех подсетей/сетов → `422` «IP x.x.x.x не принадлежит ни одной
  подсети» (отдельно для src/dst).
- src == dst или одна подсеть → путь из одного узла, роутеров нет; вердикт
  «трафик не пересекает управляемые роутеры (L2-сегмент)».
- Путей нет → отчёт с пустым `paths` + пометка «недостижимо» (не ошибка).
- `ErrTooManyPaths` / лимит хопов → `422` с подсказкой увеличить
  `MaxPaths`/`MaxHops` (громко, как у компилятора).
- Невалидный IP/proto/порт в запросе → `422` на этапе парсинга.
- Симуляция stateless: считаем первый пакет нового соединения; conntrack
  `ESTABLISHED,RELATED` в вердикте не участвует — фиксируется в `Reason`.
- Фильтрованные линки отфильтруются самим `AllSimplePaths`.

## Секция 5. Тестирование

Порядок проверки по AGENTS.md:
`go build ./... && go vet ./... && gofmt -l . && go test ./...`;
JS: `node --test 'internal/httpapi/web/*.test.js'`.

- `internal/compiler`: таблицные тесты `MatchFlow` (безусловный set,
  ipset-членство, any-proto, пустые порты правила = любые, first-match,
  промах → дефолт).
- `internal/simulate`: резолв IP→подсеть (включая адреса сетов), сборка
  `Report` на фикстуре из 2 подсетей через 1–2 роутера; drop на среднем
  роутере обрывает путь; недостижимость; one-L2-случай.
- `internal/app`: интеграционный тест `Simulate` на YAML-строках (зеркало
  тестов `Compile`); вердикты согласуются со скомпилированными правилами.
- `internal/httpapi`: хендлер-тест `POST /api/simulate` (успех, 422) по
  образцу `handlers_test.go`.
- JS: `simulate_page.test.js` (рендер отчёта, бейджи, пустые пути);
  обновить `sidebar.test.js`; после выделения `netmap.js` прогнать
