# Дизайн: E2E-сценарии, волна 2 — черновики/версии, права, табличные формы, правила, диагностика

Дата: 2026-08-30
Статус: утверждён (обсуждение в чате, весь список сценариев утверждён пользователем)

## Проблема

Волна 1 (`docs/superpowers/specs/2026-08-29-e2e-user-scenarios-design.md`,
реализована Tasks 1–8 плана 2026-08-29) покрыла: логин, создание объектов
инструментами канваса, connect-инструмент, переключение фильтра связи через
панель, переименование и удаление всех родов объектов. Но приложение имеет
ещё несколько не покрытых пользовательских поверхностей:

- **цикл работы с черновиками и версиями** — главный процесс приложения
  (создать draft → править → diff → admin подтверждает → новая версия →
  при необходимости restore) не покрыт вообще;
- **права и пользователи** — admin/user, страница `/ui/users`, logout;
- **создание объектов на табличных страницах** — волна 1 покрывала там
  только rename/delete, формы «+ подсеть», «+ набор», «+ объединение»
  и добавление членов в сеть/набор не покрыты;
- **редактор правил** `/ui/rules` (цепочки, правила, эндпоинты, линтер);
- **таблица связей** `/ui/links` (второе переключение фильтра, рядом с
  покрытой панелью на канвасе);
- **выход системы наружу**: компиляция (`/ui/compile`) и диагностика
  трафика (`/ui/diagnose`);
- **поведение редактора канваса**: перетаскивание узлов (layout),
  read-only режим текущей версии, поиск как самостоятельный флоу.

## Решение

Тот же стек и инфраструктура, что в волне 1 (без изменений):
Chromium + `firenet serve` + одноразовый Postgres в docker, `globalSetup`/
`globalTeardown` из `e2e/global-setup.js`/`global-teardown.js` переиспользуются
как есть. Паттерн сценариев тот же: arrange via API → act via UI → assert
через UI и API. Расширяются только хелперы и добавляются новые `*.spec.js`.

### Расширения хелперов (e2e/helpers/)

`helpers/api.js`:
- `login(request, creds?)` — креды параметром (по умолчанию admin из env).
- `registerUser(request, {username, password, role})` — `POST /api/users`
  (admin-request).
- `getLayout(request, draftId)` — `GET /api/drafts/{id}/layout`.
- `getCurrentTopology(request)` — `GET /api/versions/current/topology`
  (для сценариев версий).

`helpers/ui.js`:
- `loginViaUI(page, creds?)` — креды параметром (по умолчанию admin).
- `openCurrentVersion(page, path)` — открытие страницы без draft-инжекта
  (sessionStorage/localStorage чистые в новом контексте; страница читает
  `/api/versions/current/...`, см. `apiPath` в `common.js`).
- `dragNode(page, from, to)` — `page.mouse` down/move/up по `#topo-canvas`
  (мировые координаты = экранным при камере по умолчанию).

## Факты о приложении, на которые опираются сценарии

(проверены в коде на момент написания; при расхождении правится тест, не факт)

- Drafts (`web/drafts.js`): форма `#create-draft-form` (input `name`) →
  `POST /api/drafts`; таблица `#drafts-table`, кнопки в строке «Открыть»
  (redirect `/ui/topology` + setCurrentDraftID), «Изменения» (панель
  `#diff-panel`, заголовок `#diff-draft-name`, строки kind/key/change,
  конфликтные строки `.conflict-row`), «Удалить» (нативный confirm
  «Удалить черновик …»). `#confirm-btn` и чекбокс `#all-checkbox` видны
  только admin. Confirm: `POST /api/drafts/{id}/confirm` (RequireAdmin);
  успех — баннер `Черновик подтверждён как версия N` (kind "ok"), draft
  получает статус merged, текущий draft сбрасывается. У не-admin confirm
  через API — 403.
- Users (`web/users.js`): admin видит `#users-table` (строки username/role +
  кнопка «Удалить», без confirm — raw fetch DELETE) и форму
  `#create-user-form` (inputs username/password[minlength=8], select role
  user|admin). Не-admin: `#access-denied` видна, таблица и форма скрыты
  (API 403). Все users-маршруты RequireAdmin.
- History (`web/history.js`): таблица `#history-table` (id, createdAt,
  confirmedBy, note), кнопка «Дифф» → `#diff-panel` (`#diff-version-label`
  «— версия N»); admin — кнопка «Восстановить» с confirm
  «Восстановить версию N? Будет создана новая версия.» →
  `POST /api/versions/{n}/restore` (RequireAdmin), баннер
  «Создана версия N» (kind "ok"), draft сбрасывается. Diff — против
  предыдущей версии в списке (новейшая первой).
- Подсети (`web/subnets.js`): «+ подсеть» → dialog.modal (input
  `[placeholder="office-lan"]`, `[placeholder="10.0.0.0/24"]`, textarea
  `[placeholder="Заметка о подсети"]`). Клиентская валидация `draftHint`
  (пустые поля, дубликат имени, пересечение CIDR) блокирует «Сохранить»;
  плохой формат CIDR не ловится клиентом — сервер отвечает ошибкой →
  баннер «Ошибка сохранения: …». Успех — баннер «Подсети сохранены».
- Сети (`web/networks.js`): кнопки «+ сеть» нет — сети создаются на
  канвасе; страница редактирует: строка → `.icon-btn.edit` → «Изменить
  сеть» (имя `[placeholder="office"]`, member-combo input
  `[placeholder="все подсети — начните вводить для поиска"]`,
  suggestions `.member-suggestion` с текстом `name (cidr)`). Сохранить —
  `PUT topology` целиком.
- Наборы (`web/sets.js`): «+ набор» → модалка (input
  `[placeholder="blocked"]`), member-combo как у сетей, адреса — input
  `[placeholder="10.0.0.5 или 10.0.0.5/32 — Enter добавляет"]` (Enter
  добавляет адрес). Сохранение — `PUT topology`.
- Объединения (`web/unions.js`): «+ объединение» → модалка (имя
  `[placeholder="office"]`, описание `[placeholder="Заметка об
  объединении"]`); состав задаётся на канвасе (вне рамок волны 2 для
  формы, но создание/удаление записи — здесь). Удаление строки —
  `.icon-btn.delete` + confirm.
- Правила (`web/rules.js`): вкладки цепочек `.chain-tab` (+ «×» удалить
  с confirm у не-первой), «+ цепочка» `.chain-tab-add`; ⚙ «Изменить
  параметры» → select defaultAction (deny/allow/return), input имени
  цепочки, «Применить»; «+ правило» → модалка: имя
  `[placeholder="office-to-dmz"]`, src/dst member-combo
  (`[placeholder="имя, IP или CIDR — начните вводить"]`, suggestions
  включают literal «Добавить <ip/cidr>»), select action; в таблице
  строки правил, `.icon-btn.delete` с confirm «Удалить правило …»;
  «Проверить» → `.lint-panel` («Проблем не найдено» или кнопки-находки
  с severity badge). Сохранение всего документа — кнопка «Сохранить»
  (PUT rules).
- Связи (`web/links.js`): таблица: колонка «Режим» (бейдж
  «фильтрованная»/hint «обычная»), экспорт-чипы; кнопки в строке:
  «Сделать фильтрованной» (`filter: {aExports:[], bExports:[]}`),
  «Вернуть обычную» (filter удаляется), «✎ Изменить фильтры» (модалка).
  Сохранение — `PUT topology`.
- Compile (`web/compile.js`): кнопка `#compile-run` «Скомпилировать» →
  `POST .../compile`; успех — `#compile-output` содержит на каждое
  устройство `section.compile-device` с `h2` (имя), два `pre`
  (ipset/iptables) и ссылку «Скачать <file>» (Blob download).
  Ошибка — 422 → баннер ошибки (showBanner, error), output пуст.
  Ошибка достижима правилом, у которого путь src→dst физически
  отсутствует (compiler.go:345).
- Diagnose (`web/diagnose.js`): инструменты `#diag-tool-path` /
  `#diag-tool-spread`; форма пути `#diag-form`: `#diag-src`, `#diag-dst`
  (IP хостов внутри подсетей), `#diag-proto`, `#diag-dstports`, submit
  «Диагностировать» → `#diag-summary` + `#diag-paths`; отчёт не-найденного
  пути — «путь … не найден», односторонняя доступность — «Доступность в
  одну сторону: обратный путь … не найден (не хватает встречного правила
  или mirror)». Распространение: `#spread-form` с combo `#spread-src`
  (поиск по имени/CIDR/IP), submit «Показать распространение» →
  `#spread-summary`.
- Layout (web/topology.js:676 startNodeDrag): перетаскивание узла
  (mousedown на узле, move >3px, mouseup) ставит в очередь
  `set-device-position`/`set-network-position`; драг работает только для
  узлов, у которых уже есть позиция в layout (arrange задаёт её операцией
  `set-device-position`). Мировые координаты при камере по умолчанию
  совпадают с экранными.
- Read-only (`web/common.js`): без draft-id `apiPath()` ведёт на
  `/api/versions/current/…`; `renderDraftBanner` рисует
  `.draft-banner` read-only-вариант; кнопка «Сохранить» на табличных
  страницах disabled (`:disabled="!!draftHint || saving"`).
- Sidebar: `.user-box` с `.user-name` («login · admin») и кнопка
  `.logout-btn` «Выйти» → `POST /api/logout` → редирект `/login`.
- Bootstrap: сервер создаёт стартовую версию (пустой проект, т.к.
  legacy-файлы в e2e/.tmp отсутствуют) — версия 1 пустая, что удобно для
  сценариев diff/restore.

## Глобальные ограничения

**Keep-it-simple (обязательный принцип для всех сценариев):** каждый тест —
минимально возможный: arrange содержит только данные, без которых сценарий
не имеет смысла; один тест проверяет ровно одну пользовательскую задачу;
никаких запасных проверок «на всякий случай», дублирующих assert'ов,
лишних ожиданий и обобщений «под будущее». Если шаг не нужен для ответа
на вопрос сценария — его нет. (В этой среде отдельного скилла
keep-it-simple нет; принцип зафиксирован здесь явно и обязателен так же,
как скилл.)

Те же, что в волне 1:- Приложение не зависит от node; правок в `go.mod`/`internal/`/`cmd/` нет.
- Только chromium; URL от `env().baseURL`.
- Канвас-сценарии не двигают камеру (drag — исключение: он сам и есть
  перемещение узла, камера при этом не летит).
- Подготовка через `helpers/api.js`; тестируемое — действия пользователя.
- Ожидание сохранения — поллинг API (`expect.poll`/`waitTopology`).
- Сообщения/метки — как в UI (русские): «Открыть», «Изменения», «Удалить»,
  «Подтвердить», «+ подсеть», «Сохранить», «Восстановить», «Скомпилировать»,
  «Диагностировать», «Выйти».
- Мульти-пользовательские сценарии: второй пользователь регистрируется
  через API admin-запросом, логинится отдельной страницей того же
  контекста (`context.newPage()`) — cookie общая на контекст, поэтому
  разным пользователям нужны разные browser-контексты
  (`browser.newContext()`), а не страницы.

## Компромиссы (осознанно принятые)

- Сценарии диагностики требуют тяжёлого arrange (топология+подсети+
  правила через API) — это цена честного пользовательского флоу.
- Confirm/restore-сценарии завязаны на «пустая версия 1» bootstrap'а —
  если bootstrap изменится, тесты и факт сверяются с источником.
- Поведение lint-находок проверяется только на «чистых» правилах
  («Проблем не найдено»); негативные находки линтера покрывают Go-тесты
  `internal/app/lint_test.go`.
- Состав объединения задаётся на канвасе — этот флоу (контекстное меню
  «в объединение») остаётся вне рамок волны 2.

## Вне рамок

- Мультибраузерность, параллельная нагрузка, визуальные снепшоты.
- Проверка содержимого скачанных файлов (download assert по заголовку
  секции достаточно; Blob-download содержимое не проверяем).
- Контекстное меню объединений на канвасе, камера/миникарта диагностики.
